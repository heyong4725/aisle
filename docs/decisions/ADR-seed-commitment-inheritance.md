# ADR-seed-commitment-inheritance — Seed commitments in successor registrations

Status: PROPOSED — implementation interpretation under CON-15; review in PR #496.

BND-12 requires a new registration for runtime/lock drift, while BND-13/14 require withheld seed identity to remain committed and unavailable to participants. A runtime-only successor may therefore declare `seed_commitment.inherited_from` pointing to its predecessor manifest and bind that exact file under `artifacts.seed_commitment_predecessor`. The predecessor declaration hash must be internally consistent, the successor must explicitly supersede a distinct campaign id, and every seed source/derivation field must remain equal (excluding lineage). The spec, issue, purpose, and instrument set must also remain unchanged; a successor cannot use this path to reuse confirmatory seeds for calibration or a different instrument set. The existing salted digest is preserved, not regenerated or claimed verified. An explicit `seed commitment verification` gate must remain pending, preventing a frozen status even if other gates pass and a timestamp is supplied. Strict checking still refuses absent private sources; `--allow-withheld-seeds` reports them as unverified while checking lineage and all public hashes. If sources are present, their digest must match. Prior registration files remain unchanged. This is a pending-registration mechanism, not permission for scored collection or a substitute for obtaining the private sources before execution.
