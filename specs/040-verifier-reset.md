# SPEC 040 — Verifier and reset nodes

Status: DRAFT until M0. Frozen set after M0. Modules: `src/aisle/verifier/`, `src/aisle/reset/`.

Oracle verifier:
- VER-1: Subscribes `oracle_state` + `episode_goal`; publishes `episode_result` per TC-7/8. Judge logic is a pure function `judge(oracle_state, target_idx, t, cfg) -> (status, failure)` — importable and unit-testable without dora or sim.
- VER-2: Success = target box AABB-inside tray volume AND upright within 30° AND robot within home tolerance. Toppled-but-inside-and-upright-within-30° counts as SUCCESS (pre-decided; see design doc §8.3 pitfalls). All thresholds in `verifier/thresholds.toml`.
- VER-3: Failure taxonomy exactly: wrong_object, dropped, timeout, never_grasped, collision. `wrong_object` triggers the moment ANY non-target box enters the tray (safety asymmetry — do not wait for timeout).
- VER-4: The verifier is the ONLY permitted consumer of `oracle_state` (enforced by VAL-6).

Realistic verifier (Phase 2; increment one = desk T1 — ADR-realistic-verifier, D1–D6 ratified 2026-08-05; requirement wording is deliberately declarative pre-implementation, matching the prior VER-5/VER-6 style — the env-change PR that implements each ID upgrades it to RFC-2119 MUST together with the citing tests, keeping the strict M0-4 trace gate green throughout):
- VER-5: (AMENDED by ADR-realistic-verifier) the realistic judge is a five-stage pipeline — calibration (VER-8), per-camera identity (VER-9), overhead-depth 3D containment (VER-10), segmentation-assisted uprightness (VER-11), joint_state home (VER-12) — fused per VER-13 and published in the SAME `episode_result` schema as TC-7 with `verifier:"realistic"` and no schema additions; the per-stage evidence lives in the VER-14 sidecar, keyed by `goal_id`. All verifier model inference runs on CPU (D2; supersedes this spec's earlier "runs on MPS" — a verdict source does not flicker across replays, and Metal inference is nondeterministic). Weights: pinned HF snapshot revision + sha256 recorded in `verifier/models.lock` and carried into the env attestation (D3, ADR-24). Failure-class attribution (VER-3 taxonomy) remains the oracle's; the realistic `failure` field is informative and never compared classwise.
- VER-8: (stage 0 — attested calibration contract) one VERSIONED block with exact fields and conventions. Nominals derive from the frozen scene config (SCN-5 + `src/aisle/scenes/physics.toml` `[cameras]`, already env-hashed per ADR-24); the bridge publishes the REALIZED block at startup (BRG-8, SPEC 030). Schema (v1): `{calibration_version: 1, overhead: {resolution: [640, 480], fov_deg: 55, intrinsics: {fx, fy, cx, cy}, cam_to_base: {pos: [x, y, z], quat_xyzw}, depth_scale_m: 1.0}, wrist: {resolution: [320, 240], fov_deg: 70, intrinsics: {fx, fy, cx, cy}, cam_to_ee: {pos, quat_xyzw}}}`. CANONICAL CONVENTIONS (v1 = OpenCV): pixel coordinates place pixel (0,0)'s CENTER at (0,0); the optical frame is OpenCV's (+Z along the optical axis into the scene, +X image-right, +Y image-down); quaternions TC-1 xyzw; poses camera→frame in the robot-base frame; depth frames float32 METERS (`depth_scale_m` nominal exactly 1.0); `fov_deg` is the VERTICAL field of view, square pixels, `fx = fy = (h/2)/tan(radians(fov_deg)/2)`. GENESIS-TO-V1 CONVERSION (pinned Genesis v1.2.3, `genesis/vis/camera.py`): Genesis exposes `cx = w/2, cy = h/2` and samples at `u + 0.5` (pixel-corner convention) — v1 stores `cx_v1 = cx_gs - 0.5 = (w-1)/2`, `cy_v1 = cy_gs - 0.5 = (h-1)/2` (equivalent by the half-pixel shift); Genesis stores an OpenGL camera pose (look along -Z, +Y up) and converts with `diag(1,-1,-1,1)` — v1 stores the OpenCV pose, `T_v1 = T_gl @ diag(1,-1,-1,1)`. ROLL RULE: a look-at pose leaves roll free; Genesis resolves it with its default `up = (0, 0, 1)`, and v1 adopts exactly that — the VER-8 rotation predicate re-derives the expected rotation from the published position, the nominal lookat, and `up = (0,0,1)`, then converts to the OpenCV frame before comparing. The WRIST camera has no static camera→base pose (it rides the EE): its calibration is the static `cam_to_ee` mount (nominal: `pos = wrist_offset_m`, rotation = the scene's mount orientation `wrist_rotation_xyzw` (SCN-5, `physics.toml [cameras]`) expressed in the same OpenCV convention — DR never perturbs it; AMENDED 2026-08-07, issue #109: this previously read "the identity mount", which described a camera aimed back UP THE ARM. The scene attached the wrist camera with no orientation, the nominal faithfully described that, and the two agreed with each other while no wrist frame in any recorded run ever contained the workspace. The mount is now an explicit, REQUIRED input to the v1 builder so a nominal block cannot describe a camera the scene did not build, and a sim conformance test pins `cam_to_ee` against the realized Genesis transform AND asserts the optical axis points along the EE link's +Z approach direction), and any wrist-frame tray-ROI projection composes `cam_to_ee` with the EE→base pose from FK of the `joint_state` whose sim stamp matches the judged frame's (TC metadata correlation). Static back-projection (VER-10/VER-11 3D work) is OVERHEAD-scoped per D4. Stage-0 refusal predicate — each check independent, any failure refuses to judge (fail closed): (a) block present, well-formed, `calibration_version` supported; (b) every intrinsics field and `depth_scale_m` EXACTLY nominal after conversion (DR never perturbs them); (c) overhead `cam_to_base.pos` within `camera_jitter_m/2` of nominal PER AXIS (the DR jitter is per-axis uniform ±`camera_jitter_m/2`); (d) overhead rotation within 1.0° of the re-derived expected rotation (position + nominal lookat + `up=(0,0,1)`, converted) — a rotated-in-place camera at a correct position refuses; (e) wrist `cam_to_ee` exactly nominal. The sha256 of the canonical (sorted-keys) JSON of the published block is recorded in the run manifest. On HARDWARE (Phase 4) the same v1 block is produced from the measured-calibration artifact (`env/calibration.toml`, per-device — recorded as an addendum to the accepted realistic-verifier ADR, CON-15) instead of the scene files — fields, conventions, and refusal identical. Acceptance: four independent corruption tests (depth scale, one intrinsic, translation beyond bound, rotation beyond bound) each refusing.
- VER-9: (stage 1 — identity, with the VER-3 safety asymmetry preserved ACROSS TIME) OWLv2 (`google/owlv2-base-patch16-ensemble`, D1) free-text queries for EVERY med class, run per camera (overhead RGB and wrist RGB) on every JUDGED frame: the terminal frame plus checkpoint frames sampled every `checkpoint_period_s` (`verifier/thresholds.toml`, default 5.0 s) from goal receipt to episode result. A camera's identity vote is success iff the TARGET class detects inside the tray region at ≥ the score threshold AND the episode's WRONG-OBJECT LATCH is clear. The latch is episode-scoped, goal-keyed and PER-CAMERA (AMENDED 2026-08-08, issue #107): the moment any judged frame FROM A GIVEN CAMERA detects a non-target med class inside the tray region, that camera's identity vote is FAILED through the terminal verdict. It was cross-camera, which let the wrist -- which classifies ~21 px boxes unreliably at close range and frames neighbours the overhead never has in view -- veto the overhead's vote: 2 of 5 episodes in the first VER-6 run were failed that way while the overhead's own detections were healthy. A camera that cannot tell the classes apart does not get to overrule one that can — mirroring VER-3's immediate `wrong_object` rule, so neither a simultaneous target-plus-wrong-item tray NOR a transient (wrong item enters, is removed, target delivered) can fuse to success (class naming stays oracle-attributed per VER-5). A transient that falls entirely BETWEEN checkpoints is the cadence-bounded residual that VER-6's false-success rate exists to measure — tightening `checkpoint_period_s` is the knob, and the fidelity report notes the configured value. Per-frame, per-camera votes, per-class scores, and latch events (with sim stamps) are recorded in the VER-14 sidecar. Acceptance includes BOTH the simultaneous case and the transient sequence (non-target enters at a checkpoint → leaves → target delivered → FAIL), asserted on the camera whose frames carry the non-target. CALIBRATED ENVELOPE (amended 2026-08-07, issue #108): the query vocabulary and score threshold in `verifier/thresholds.toml` are calibrated for the OVERHEAD camera under exactly the following SCN-6 toggle combinations, each measured over 5 med classes x 2 seeds: (1) all toggles off; (2) `lighting`; (3) `textures`; (4) `camera_jitter`; (5) `lighting`+`textures`; (6) `lighting`+`camera_jitter`; (7) `textures`+`camera_jitter` — 70 of 70 cells produced a correct target vote with no wrong-object latch. EVERY OTHER SCN-6 configuration is OUT OF ENVELOPE, and running the identity stage there is not a VER-9 conformance claim. That explicitly includes (a) `lighting`+`textures`+`camera_jitter`, which is measured BROKEN — a correct delivery is detected as a different med class and sets the permanent wrong-object latch — and (b) any configuration enabling `friction_jitter`, which was not swept. The three-axis failure is not a calibration error and no threshold fixes it: genuine in-tray detections span 0.054–0.35 and the misclassification sits inside that band, because the meds are ~21 px untextured boxes whose only identity signal is colour and `textures` randomizes exactly that. Widening the envelope means measuring the additional combinations, or giving identity a colour-independent signal (a shape/size prior, or a different model class) with its own evidence — never a re-tuned threshold. The same envelope is recorded alongside the values it constrains in `verifier/thresholds.toml`.
- VER-10: (stage 2 — containment) tray-volume containment from OVERHEAD depth only (D4 — the wrist camera publishes no depth; `depth_wrist` is a NAMED follow-up taken only if VER-14's per-stage disagreement breakdown shows stages 2–3 dominating).
- VER-11: (stage 3 — upright) segmentation-assisted uprightness (MobileSAM-class mask + depth extent, D6) with the SAME 30° threshold as VER-2.
- VER-12: (stage 4 — home) joint_state within the SAME home tolerance as VER-2 — one threshold, one source (`verifier/thresholds.toml`).
- VER-13: (fusion — explicit and Boolean) realistic success iff identity_overhead AND containment AND upright AND home. AMENDED 2026-08-08 (issue #107): identity_wrist is CORROBORATING, recorded in the VER-14 sidecar and reported by VER-6, but it does not gate the verdict. Measured cause: after the wrist camera's mount was fixed (#109/#110) it does produce passing votes, but only inside a ~1 s window around release that the 5 s checkpoint cadence samples about 2 times in 5, and every false fail in the first VER-6 run was wrist-driven while the overhead contributed NONE. Recomputed over 25 recorded oracle successes (seeds 3..7 and 10..29) plus 6 induced failures, this amendment together with the per-camera latch above lifts positive-side agreement 0.12 -> 0.32 (combined 0.29 -> 0.45) with the false-SUCCESS rate unchanged at 0 of 6 — it does not buy agreement by becoming permissive. Each change ALONE is worthless: dropping the wrist from the gate leaves 0.20 while a wrist latch still poisons the overhead vote, and scoping the latch alone leaves 0.12. Note the residual is still large — the wrist is the biggest single contributor but not the only one (containment blocks 15 of 20 and the overhead 13 of 20 on the larger run), so this amendment improves the verifier without making it usable for A7 on its own. ACCEPTED COST, stated so it is not rediscovered as a defect: a wrong object visible ONLY to the wrist (occluded from overhead, e.g. by the arm) no longer fails the episode. That is a narrowing of VER-3's asymmetry in one specific direction, taken deliberately because the wrist's classification is the least reliable evidence in the stack. Restoring the wrist to the required set requires evidence that it detects reliably — not a re-tuned threshold. A stage unable to produce a verdict (missing frame, VER-8 refusal, model error) makes the episode's realistic verdict FAIL with that stage recorded as `error` in the VER-14 sidecar — fail closed, never skip-and-fuse.
- VER-14: (per-episode stage record — a SIDECAR, so TC-7's stable `episode_result` schema is untouched) `realistic.py` appends one JSON object per judged episode to `runs/<id>/verifier_stages.jsonl`: `{goal_id, verifier: "realistic", latch: {latched: bool, first_event: {sim_time_ns, camera, med_class} | null}, stages: {calibration, identity_overhead, identity_wrist, containment, upright, home}}`. The two identity stages carry the FULL judged-frame timeline: `{vote: pass|fail|error, frames: [{sim_time_ns, per_class_scores, target_in_tray: bool, non_target_in_tray: bool}]}` — one entry per judged frame (checkpoints + terminal, VER-9), so the checkpoint cadence and every latch contribution are auditable. The non-identity stages carry `{vote: pass|fail|error, measurement}` with the stage's measurement being: calibration — the nominal-vs-actual deviations; containment — signed margin (m); upright — tilt angle (deg); home — max joint residual (rad). `goal_id` is the correlation key to `episode_result` and to VER-6; `harness/fidelity.py` consumes this same schema (one shared module constant defines it, and the shape test covers the identity frame arrays and the latch object) so disagreements are attributable to a stage — the decision evidence for the D4 `depth_wrist` trigger.
- VER-6: (AMENDED, D5) `harness/fidelity.py` replays N episodes through BOTH verifiers and reports, with explicit denominators: `agreement` = matching success bits / N; `false_success_rate` = |realistic success AND oracle fail| / |oracle fail| (the dangerous direction for A7); `false_fail_rate` = |realistic fail AND oracle success| / |oracle success|. An empty denominator yields JSON `null`, never 0.0; N=0 refuses (CON-8). Per-run manifests carry the four underlying counts plus the three rates.
- VER-7: (determinism replay, D2) every verifier model is run twice on committed golden frames within one process AND across two separate processes; the raw outputs (logits/boxes/masks) are bit-identical, pinning the no-flicker guarantee against torch/transformers upgrades rather than assuming it from the powder-spike precedent. This is the acceptance gate for any future model/framework bump.

Reset node:
- RST-1: Teleport reset: delegate to bridge (BRG-4); MUST complete <2 s.
- RST-2: Behavioral reset: command the robot to return the target box to a sampled shelf pose, verify with the realistic verifier, retry ≤3, then fall back to teleport with `fallback:true` in reply metadata (never hang the loop).

Acceptance: `tests/unit/test_judge.py` — table-driven cases for every VER-3 class + VER-2 edge poses (≥20 cases, cites VER-1..3); `tests/graph/test_verifier_wiring.py::test_oracle_only_edge` (VER-4); `tests/sim/test_behavioral_reset.py` (RST-2, marker sim, Phase 2 gate). Realistic increment one (env-change PR, ADR-realistic-verifier sketch step 2): fusion truth table incl. the fail-closed stage-error rows (VER-13), the four independent calibration-corruption refusals (VER-8), and BOTH VER-9 rejection cases (simultaneous, and the transient latch sequence) as pure unit tests; golden-frame fixtures for VER-9..VER-12; the VER-7 replay test; VER-6/VER-14 shapes covered by `harness/fidelity.py` unit tests (sketch step 3). Each implementing PR upgrades its IDs to MUST wording alongside the citing tests (HAR-9).
