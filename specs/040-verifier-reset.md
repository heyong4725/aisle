# SPEC 040 — Verifier and reset nodes

Status: DRAFT until M0. Frozen set after M0. Modules: `src/aisle/verifier/`, `src/aisle/reset/`.

Oracle verifier:
- VER-1: Subscribes `oracle_state` + `episode_goal`; publishes `episode_result` per TC-7/8. Judge logic is a pure function `judge(oracle_state, target_idx, t, cfg) -> (status, failure)` — importable and unit-testable without dora or sim.
- VER-2: Success = target box AABB-inside tray volume AND upright within 30° AND robot within home tolerance. Toppled-but-inside-and-upright-within-30° counts as SUCCESS (pre-decided; see design doc §8.3 pitfalls). All thresholds in `verifier/thresholds.toml`.
- VER-3: Failure taxonomy exactly: wrong_object, dropped, timeout, never_grasped, collision. `wrong_object` triggers the moment ANY non-target box enters the tray (safety asymmetry — do not wait for timeout).
- VER-4: The verifier is the ONLY permitted consumer of `oracle_state` (enforced by VAL-6).

Realistic verifier (Phase 2; increment one = desk T1 — ADR-realistic-verifier, D1–D6 ratified 2026-08-05; requirement wording is deliberately declarative pre-implementation, matching the prior VER-5/VER-6 style — the env-change PR that implements each ID upgrades it to RFC-2119 MUST together with the citing tests, keeping the strict M0-4 trace gate green throughout):
- VER-5: (AMENDED by ADR-realistic-verifier) the realistic judge is a five-stage pipeline — calibration (VER-8), per-camera identity (VER-9), overhead-depth 3D containment (VER-10), segmentation-assisted uprightness (VER-11), joint_state home (VER-12) — fused per VER-13 and published in the SAME `episode_result` schema as TC-7 with `verifier:"realistic"` and no schema additions; the per-stage evidence lives in the VER-14 sidecar, keyed by `goal_id`. All verifier model inference runs on CPU (D2; supersedes this spec's earlier "runs on MPS" — a verdict source does not flicker across replays, and Metal inference is nondeterministic). Weights: pinned HF snapshot revision + sha256 recorded in `verifier/models.lock` and carried into the env attestation (D3, ADR-24). Failure-class attribution (VER-3 taxonomy) remains the oracle's; the realistic `failure` field is informative and never compared classwise.
- VER-8: (stage 0 — attested calibration contract) the NOMINAL calibration is the frozen scene config — SCN-5's resolutions/FOVs plus `src/aisle/scenes/physics.toml` `[cameras]` (positions, lookat, wrist offset) — already env-hashed with the frozen set (ADR-24). At graph start the bridge publishes the ACTUAL per-camera calibration in `bridge_info` metadata, after seeded DR camera jitter: intrinsics (fx, fy, cx, cy derived from resolution+FOV), extrinsic camera→robot-base pose (TC-1 xyzw quaternion, robot-base frame), and the depth scale in meters. Stage 0 refuses to judge (fail closed) unless the block is present and well-formed, intrinsics and depth scale match the nominals exactly (DR never perturbs them), and each extrinsic position deviates from its nominal by ≤ the attested `camera_jitter_m` bound. The sha256 of the canonical (sorted-keys) JSON of the published block is recorded in the run manifest for audit.
- VER-9: (stage 1 — identity, with the VER-3 safety asymmetry preserved) OWLv2 (`google/owlv2-base-patch16-ensemble`, D1) free-text queries for EVERY med class, run per camera (overhead RGB and wrist RGB). A camera's identity vote is success iff the TARGET class detects inside the tray region at ≥ the score threshold in `verifier/thresholds.toml` AND NO non-target med class detects inside the tray region at that threshold — a detected non-target in the tray rejects, mirroring VER-3's immediate `wrong_object` rule so a target-plus-wrong-item tray cannot fuse to success by construction (class naming stays oracle-attributed per VER-5). Per-camera votes and per-class scores are recorded in the VER-14 sidecar. Acceptance includes a target-present-plus-non-target-in-tray case that fuses to FAIL.
- VER-10: (stage 2 — containment) tray-volume containment from OVERHEAD depth only (D4 — the wrist camera publishes no depth; `depth_wrist` is a NAMED follow-up taken only if VER-14's per-stage disagreement breakdown shows stages 2–3 dominating).
- VER-11: (stage 3 — upright) segmentation-assisted uprightness (MobileSAM-class mask + depth extent, D6) with the SAME 30° threshold as VER-2.
- VER-12: (stage 4 — home) joint_state within the SAME home tolerance as VER-2 — one threshold, one source (`verifier/thresholds.toml`).
- VER-13: (fusion — explicit and Boolean) realistic success iff identity_overhead AND identity_wrist AND containment AND upright AND home. A stage unable to produce a verdict (missing frame, VER-8 refusal, model error) makes the episode's realistic verdict FAIL with that stage recorded as `error` in the VER-14 sidecar — fail closed, never skip-and-fuse.
- VER-14: (per-episode stage record — a SIDECAR, so TC-7's stable `episode_result` schema is untouched) `realistic.py` appends one JSON object per judged episode to `runs/<id>/verifier_stages.jsonl`: `{goal_id, verifier: "realistic", stages: {calibration, identity_overhead, identity_wrist, containment, upright, home}}`, each stage `{vote: pass|fail|error, measurement}` with the stage's measurement being: calibration — the nominal-vs-actual deviations; identity — per-class max scores; containment — signed margin (m); upright — tilt angle (deg); home — max joint residual (rad). `goal_id` is the correlation key to `episode_result` and to VER-6; `harness/fidelity.py` consumes this same schema (one shared module constant defines it) so disagreements are attributable to a stage — the decision evidence for the D4 `depth_wrist` trigger.
- VER-6: (AMENDED, D5) `harness/fidelity.py` replays N episodes through BOTH verifiers and reports, with explicit denominators: `agreement` = matching success bits / N; `false_success_rate` = |realistic success AND oracle fail| / |oracle fail| (the dangerous direction for A7); `false_fail_rate` = |realistic fail AND oracle success| / |oracle success|. An empty denominator yields JSON `null`, never 0.0; N=0 refuses (CON-8). Per-run manifests carry the four underlying counts plus the three rates.
- VER-7: (determinism replay, D2) every verifier model is run twice on committed golden frames within one process AND across two separate processes; the raw outputs (logits/boxes/masks) are bit-identical, pinning the no-flicker guarantee against torch/transformers upgrades rather than assuming it from the powder-spike precedent. This is the acceptance gate for any future model/framework bump.

Reset node:
- RST-1: Teleport reset: delegate to bridge (BRG-4); MUST complete <2 s.
- RST-2: Behavioral reset: command the robot to return the target box to a sampled shelf pose, verify with the realistic verifier, retry ≤3, then fall back to teleport with `fallback:true` in reply metadata (never hang the loop).

Acceptance: `tests/unit/test_judge.py` — table-driven cases for every VER-3 class + VER-2 edge poses (≥20 cases, cites VER-1..3); `tests/graph/test_verifier_wiring.py::test_oracle_only_edge` (VER-4); `tests/sim/test_behavioral_reset.py` (RST-2, marker sim, Phase 2 gate). Realistic increment one (env-change PR, ADR-realistic-verifier sketch step 2): fusion truth table incl. the fail-closed stage-error rows (VER-13), the calibration refusal predicate (VER-8), and the target-plus-non-target-in-tray rejection (VER-9) as pure unit tests; golden-frame fixtures for VER-9..VER-12; the VER-7 replay test; VER-6/VER-14 shapes covered by `harness/fidelity.py` unit tests (sketch step 3). Each implementing PR upgrades its IDs to MUST wording alongside the citing tests (HAR-9).
