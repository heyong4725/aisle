# SPEC 500 — Replicated typed-dataflow versus monolithic causal study

Status: PROPOSED, HUMAN-REVIEW GATED. Issue: #347. This contract pre-registers
the decisive AISLE causal comparison but authorizes no scored collection. It
depends on passing and freezing the issue #344 monolithic parity, issue #345
statistics, issue #346 non-oracle task band, and issue #353 treatment-integrity
gates. Results update the issue #358 claim matrix regardless of direction.

The estimand is the effect of the bundled typed-dataflow engineering surface,
not static typing alone: capability/graph composition, registry resolution,
static validation and diagnostics, and dora runtime representation versus one
ordinary orchestration module over identical robot primitives and authority.

## Hypothesis, unit, and outcomes

- CSE-1: The primary experimental unit MUST be one fresh coding-agent session.
  Its treatment is `typed_dataflow` or `monolithic`; nested edits, tool calls,
  rollouts, artifacts, episodes, held-out seeds, commands, and events MUST NOT be
  treated as independent treatment replicates. The frozen primary estimand MUST
  be the session-success risk difference `typed_dataflow - monolithic`, reported
  overall and by pre-declared agent-system and task strata with issue #345 exact
  arm intervals and Newcombe interval.
- CSE-2: Session success MUST mean that one finalized deliverable, submitted by
  the frozen deadline rule, launches through its arm's registered launcher and
  passes the selected task card's hidden paired held-out acceptance function
  within every token, wall, rollout, simulator, and tool-authority budget. The
  protocol MUST freeze whether explicit `submit` or the last eligible snapshot
  selects the artifact. Multiple snapshots, retries, or held-out episodes MUST
  NOT create best-of-N session success, and held-out feedback MUST arrive only
  after the agent process terminates.
- CSE-3: The protocol MUST pre-register a directional primary superiority rule,
  smallest effect of interest, alpha, target power, baseline assumptions,
  multiplicity treatment, and decision language. A point estimate, p-value, or
  interval that does not meet the frozen rule MUST NOT be reframed as support.
  Negative, null, imprecise, or monolithic-favoring estimates are valid final
  outcomes and MUST map to `weakened`, `rejected`, or `undecidable` claim status
  by the frozen issue #358 rule; only the registered superiority decision MAY
  map the causal claim to `supported`.
- CSE-4: Secondary session-level outcomes MUST include validation and launch
  failure classes; held-out quality and per-seed results; time to first accepted
  system with censoring; input/output/total tokens; tool calls; wall and active
  agent time; simulator work; rollout count; safety interventions; deliverable
  size/change history; and exclusions. The protocol MUST name units,
  aggregation, censoring, direction, and inferential or descriptive status for
  each; exploratory outcomes MUST be labeled and cannot rescue the primary.
- CSE-5: An `equal-quality` cost claim is permitted only if pre-registered
  equivalence tests pass for both session acceptance probability and accepted
  held-out quality using frozen practical margins. Otherwise resource outcomes
  MUST be reported as unconditional or censored session estimands without the
  phrase `at equal quality`. Conditioning on successful sessions alone MUST NOT
  support a causal cost claim.

## Replication, allocation, and power

- CSE-6: The campaign MUST include at least two independently supplied coding-
  agent systems whose provider, served model identity, agent implementation and
  binary hash, settings, and context policy are frozen. Each system MUST use
  fresh isolated sessions with no shared memory or deliverables. A model alias,
  CLI drift, provider interruption, or context carryover MUST follow the frozen
  treatment-integrity classification rather than be silently accepted.
- CSE-7: Allocation MUST be generated by a campaign-owned seeded randomizer
  before scored data, concealed until launch, and balanced in temporal blocks
  within every agent-system × selected-task stratum. Blocks MUST record order,
  host/resource pool, planned start window, assignment, and host-load baseline.
  Arm order MUST vary within blocks; discretionary scheduling, alternating from
  memory, or filling one arm before the other is forbidden.
- CSE-8: The issue #345 power CLI MUST determine sample size from pilot-only
  control success, the frozen smallest risk difference, alpha, target power,
  allocation, and attrition sensitivity. Ten randomized assignments per arm in
  each agent-system × selected-task stratum is an absolute floor, not the target;
  the larger powered or floor count governs. Sample size, full block list, and
  stopping rule MUST be frozen before any scored outcome, with no optional
  stopping, adaptive reallocation, or post-result extension.
- CSE-9: Every session within a paired block MUST receive the same selected task
  version and semantically identical development distribution, hidden held-out
  seed set, prompts apart from declared representation instructions, budget,
  tool and approval policy, environment, primitive/evaluator versions, and
  host-resource class. Hidden seed values and task truth MUST remain evaluator-
  private; pairing improves precision but does not turn seeds into the
  experimental unit.

## Prerequisite and treatment-integrity gate

- CSE-10: Scored collection MUST refuse unless machine-readable gate records
  show every #344 treatment table/interface/expert parity check, #345 power and
  independent statistical review, #346 perception/task/pilot/freeze/leakage
  check, and #353 confinement/mutation/agent-path check passing at immutable
  hashes. A warning, human override, stale report, partial agent path, unresolved
  exclusion, or missing raw gate record MUST keep the campaign locked.
- CSE-11: Each session MUST use the common evidence envelope and sealed
  treatment manifest. The independent integrity controller MUST attest the
  visible tree, prompt, model/CLI, HOME/config/cache, credentials, environment,
  tools, network/process/filesystem authority, budgets, treatment artifacts,
  randomization block, host load, raw evidence sink, and postflight hashes.
  Session-side code MUST NOT author or suppress its own integrity verdict.
- CSE-12: Same-experiment prompts, transcripts, analyses, aggregate results,
  treatment effects, prior-arm deliverables, caches, refs, skills, operator
  hints, and evaluator-private assets MUST be unavailable to every later
  session. Independently built views plus seeded contamination sentinels and
  access logs MUST demonstrate exclusion. A leak invalidates affected blocks
  under the frozen rule; deleting or merely not mentioning leaked material does
  not repair them.

## Lifecycle, exclusions, and deviations

- CSE-13: The retained assignment ledger MUST include every planned,
  randomized, launched, completed, submitted, evaluated, censored, failed,
  infrastructure-invalid, and excluded session with stable ids, timestamps,
  block/treatment/agent/task, reason, budget state, evidence hashes, and any
  linked rerun. Validation failures, authored runtime failures, and treatment-
  surface crashes are session outcomes, not infrastructure exclusions.
- CSE-14: Infrastructure exclusions MUST use pre-registered, arm-neutral facts
  determined by the independent controller. Originals MUST remain retained and
  MUST NOT be replaced in place; a permitted rerun receives a new randomized id
  and follows the frozen rule. Primary and sensitivity reports MUST expose
  exclusion rates by arm and bounding analyses that assign excluded outcomes in
  arm-adverse and arm-favorable directions. Informative or imbalanced
  exclusions MUST limit the causal interpretation even when the main estimate
  is favorable.
- CSE-15: A content-addressed protocol-freeze manifest MUST bind hypotheses,
  endpoints, margins, sample/power inputs, blocks and randomization seed,
  stopping/exclusion/rerun/deviation rules, agent systems, tasks/heldouts,
  treatment surfaces and parity evidence, prompts, budgets/authority,
  confinement, environment, evidence schemas, session launcher, analyzer and
  fixtures, reporting templates, and exact commands. It MUST be externally
  timestamped and independently reviewed before scored data. Any behavior-
  affecting change afterward starts a new version/campaign or a documented
  deviation whose affected estimates are clearly separated; confirmatory data
  MUST NOT silently revise the protocol.

## Analysis, legibility, and release evidence

- CSE-16: The registered CON-8 analyzer MUST regenerate a machine-readable
  result, arm/stratum tables, intervals/equivalence decisions, censor tables,
  exclusion sensitivities, raw session-point export, and session-flow diagram
  from named frozen records. It MUST fail on missing assignments/evidence,
  duplicate or mixed campaign ids, block/arm mismatch, pilot rows,
  post-stopping rows, nested-unit inflation, changed protocol/analyzer hash, or
  any count/table that does not reconcile byte-for-byte.
- CSE-17: The primary report MUST show each agent-system × task estimate before
  any pooled estimate, prespecified heterogeneity/interaction summaries,
  completed block counts, all negative and null results, assumptions, protocol
  deviations, and limitations of the bundled treatment. Pooling MUST use the
  frozen standardization/weighting rule and MUST NOT hide reversal or a failed
  stratum.
- CSE-18: Artifact legibility MAY remain a secondary outcome only if the frozen
  protocol defines the rubric, examples, practical margin, rater number,
  adjudication, inter-rater measure, and missing-rating rule before collection.
  Raters MUST be blinded to agent identity, quantitative outcomes, session
  order, and study hypothesis; because artifact representation may reveal the
  arm, treatment guesses and achieved blinding MUST be reported. If this design
  is not ratified before freeze, legibility is dropped rather than scored after
  seeing artifacts.
- CSE-19: Release evidence MUST retain the protocol and timestamp, gate reports,
  randomization/block ledger, all session and integrity records, transcripts,
  tool/budget logs, submitted deliverables, hidden-evaluation records after
  unsealing, raw/derived hashes, analyzer/fixtures, tables/diagram, deviation
  log, claim disposition, and exact regeneration command. Redaction may remove
  credentials or personal data only by a logged deterministic process that
  preserves non-secret evidence and hashes the released/redacted variants.

## Required fixtures and limitations

Fixtures cover every lifecycle state, treatment-surface versus infrastructure
failure, imbalanced exclusions, permitted reruns, contamination, model drift,
block imbalance, hidden-seed mismatch, best-of-N submission attempts, censoring,
equivalence boundaries, heterogeneous/reversed strata, null and monolithic-
favoring effects, legibility missingness, protocol drift, and raw-input hash
changes. A conforming study estimates this bundled interface effect in the
selected simulation tasks and agent systems; it does not isolate one mechanism,
generalize to every coding agent or robot task, or establish hardware validity.
