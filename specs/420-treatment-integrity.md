# SPEC 420 — Confirmatory treatment integrity and sealed agent views

Status: PROPOSED, HUMAN-REVIEW GATED. Issue: #353. This contract integrates the
lessons of issues #96, #245, #266, #282, and #283 for new confirmatory
campaigns. It does not retroactively attest historical sessions. Depends on
CON-5, CON-8, HAR-2/HAR-4/HAR-5, SPEC 400, and the hidden-controller contracts
for issues #348 and #350.

The **treatment tuple** is every input that can change what an autonomous
coding session sees, can do, or is charged for. A prompt/model/commit triple is
not sufficient treatment identity.

## Complete treatment tuple

- TRT-1: Before any session-side process starts, preflight MUST emit one
  machine-readable treatment manifest with a schema version and immutable id.
  It MUST include repository commit/tree and visible-file manifest; model served
  identity, agent CLI revision/binary hash, sampling/configuration, system
  prompt/research-contract hash, approval and tool policy; runtime CLI/API
  binary hashes; dependency/environment fingerprint, simulator backend, and
  platform; credential source class, HOME/config/cache state, network policy,
  allowed external tools, prior findings/skills/context; budgets and accounting
  units; temporal block, randomization assignment, and host-load baseline.
- TRT-2: Preflight MUST refuse absent, placeholder, ambiguous, or internally
  inconsistent treatment fields. A human-readable version string MUST NOT
  substitute for a binary/content hash or exact served-model identity. Secrets
  MUST be represented by redacted provenance and policy metadata, never copied
  into the retained manifest.
- TRT-3: The repository view MUST be created from an explicit allowlist at a
  pinned commit and record every visible path plus content hash. Same-experiment
  analyses, prior-arm deliverables, hidden seeds, fault definitions, injector
  ledgers, reference repairs, and evaluator-private material MUST be absent from
  the visible view and denied by the confinement policy.
- TRT-4: Claude and Codex campaign paths MUST implement the same filesystem,
  process, network, tool, budget, evidence, and evaluator authority. Necessary
  vendor-authentication differences MUST be named in the manifest and tested as
  credentials only, not as an unrecorded knowledge or tool channel.

## Sealed execution and hidden material

- TRT-5: A session MUST run through an external, campaign-owned confinement
  adapter rather than relying on prompt prohibitions or agent self-restraint.
  The adapter MUST deny reads outside approved system/runtime roots and the
  agent-visible tree, deny writes outside declared session outputs, and enforce
  the declared process/network/tool policy. Starting without an active verified
  adapter MUST fail closed before budget spend.
- TRT-6: Hidden evaluator and fault material MUST live outside every
  agent-visible worktree and retained git object namespace. Preflight MUST prove
  that direct paths, parent traversal, symlinks, alternate worktrees, git object
  reads, subprocesses, and allowed tool surfaces cannot return hidden bytes.
  Merely omitting a path from the prompt or directory listing is insufficient.
- TRT-7: The isolated HOME, agent config homes, XDG state/cache, credentials,
  environment variables, inherited file descriptors, and local service/socket
  endpoints MUST start from a declared baseline. Ambient operator memory,
  credentials, caches, shell startup files, and unrelated environment variables
  MUST NOT enter the session.
- TRT-8: Randomization MUST be generated by the controller from a frozen seed,
  recorded as temporal blocks, and concealed until assignment. Preflight and
  postflight MUST record host-load observations using the frozen sampling rule;
  arm order or load anomalies MUST remain visible to the analyzer.

## Postflight, retention, and fail-closed audit

- TRT-9: Postflight MUST recompute the agent-visible tree, critical binary and
  policy hashes, environment identity, model/CLI identity, confinement status,
  and hidden-material access log. Any drift, unreadable audit source, or
  unresolved model identity MUST classify the session as an infrastructure
  exclusion rather than an agent outcome.
- TRT-10: Every randomized assignment and started session MUST retain its raw
  stdout transcript, stderr, tool/audit log, deliverable tree, idea ledger,
  preflight/postflight manifests, budget samples, randomization/block record,
  and exclusion reason before worktree cleanup. Retention failure MUST be loud
  and MUST block use of the session in an estimate.
- TRT-11: Credential scrubbing MUST occur after every auth probe and session,
  including aborted launches, without deleting retained non-secret evidence.
  The postflight record MUST prove the canonical credential locations were
  scrubbed; credential bytes or refresh tokens MUST NOT enter archives.
- TRT-12: A later arm MUST start from a view built independently from the frozen
  baseline, not from a predecessor worktree, cache, HOME, transcript, analysis,
  or deliverable ref. A seeded contamination sentinel MUST demonstrate that
  same-experiment material is excluded without revealing hidden content.

## Mutation and protocol-freeze gates

- TRT-13: Mutation tests MUST independently remove or drift every TRT-1
  treatment component and demonstrate a preflight/postflight refusal or
  infrastructure exclusion. The mutation report MUST include detection rate,
  false-alarm fixtures, and any surviving blind spot; a surviving critical
  mutation blocks confirmatory collection.
- TRT-14: Before protocol freeze, both Claude and Codex paths MUST pass the same
  sealed-view conformance suite, including denied hidden reads and retained
  transcript/deliverable/idea/tool-policy evidence. Passing only one agent path
  MUST block both-arm confirmatory claims.
- TRT-15: The frozen protocol MUST record hashes for the allowlist, treatment
  schema, preflight/postflight implementation, confinement profile and adapter,
  session launcher, research contract, randomization plan, and retention
  schema. Any post-freeze change MUST follow the documented deviation/new-study
  process rather than silently updating the treatment.

## Required fixtures

Acceptance coverage includes every unresolved treatment field; served-model
alias drift; CLI/runtime binary drift; ambient HOME/XDG/env/fd/socket leakage;
absolute, parent, symlink, alternate-worktree, git-object, and subprocess hidden
reads; tool/network policy violations; same-experiment contamination; host-load
and temporal-block capture; interrupted credential scrubbing; archive failure;
and equivalent Claude/Codex manifests. Synthetic hidden bytes never contain a
real fault identity or credential.
