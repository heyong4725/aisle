# SPEC 210 — Mobility contract extension (mobile profile)

Status: DRAFT, post-M0. Class C once stable (extends SPEC 010).
Adds a `mobile` embodiment profile: differential-drive base + arm. Fixed-base
profiles are untouched; every SPEC 010 topic and rule still applies.

- MOB-1: New topics — `base_pose` out Float32[3] (x, y, yaw; store frame) @50 Hz; `base_cmd` in Float32[2] (v m/s, omega rad/s) ≤50 Hz; `base_scan` out Float32[n] (planar ranges) @10 Hz, meta {angle_min, angle_max, n}. TC-2 metadata rules apply.
- MOB-2: Navigation is a dora ACTION (goal_id pattern, mirrors TC-7): goal `nav_goal` JSON {location: str | pose:[x,y,yaw]} where named locations resolve via `scenes/locations.toml` (counter, bin, shelf_zone_A...); feedback {t, dist_remaining} ≥2 Hz measured in SIMULATED time under simulation and WALL/device time on hardware (the TC-4 clock rule); result {status: success|fail, failure: null|blocked|timeout|no_sim_clock, t_end}.
  `no_sim_clock` (added for issue #182, spec-change PR #188) reports that the goal was ended because its pose stream carried no usable sim stamp for long enough that the machine could no longer enforce its own stall or timeout budget — a nav goal MUST NOT steer indefinitely on a clock that never arrived. It is a diagnosis, not a safety bound: the MOB-3 guard's blind-drive stop is what bounds the motion. Consumers MUST treat it as terminal for the goal; note that it is NOT transient, so a bare retry re-arms the same condition.
- MOB-3: Budget guard extension (SPEC 080): base velocity limits, keep-out zones from `env/limits.toml` (e.g., min distance to shelves while arm is extended), and a mutual-exclusion rule — arm motion class and base motion above v_creep MUST NOT be commanded simultaneously (clamp base to v_creep, emit violation). The arm-motion class persists for `arm_motion_hold_s` on the command's CONTRACT clock: `sim_time_ns` in simulation and monotonic device time on hardware. A process WALL clock MAY provide a fail-closed liveness backstop but MUST NOT shorten or extend the simulated hold. A missing, zero, malformed, or regressing command stamp MUST fail closed while arm motion may be active. In an ADR-30 lockstep graph the wall net's SWEEP emissions are confined to non-attesting modes (ADR-30 §3): the guard's sim-time staleness check is the sole stop path there, and wall-clocked handlers abort or log but never emit turn-stamped commands.
- MOB-4: The `mobile` profile's arm topics are identical to the fixed-base contract (TC-5); a graph valid for `franka` desk tasks MUST validate unchanged for the mobile profile's arm subtree (embodiment field extended, VAL EMBODIMENT_MISMATCH covers base-requiring nodes on fixed-base graphs).
- MOB-5: Store frame: all base topics in a fixed store frame defined by the scene; the bridge publishes `frame_info` once at startup (transform base-frame ↔ store-frame conventions documented in CONTRACT.md §frames).
